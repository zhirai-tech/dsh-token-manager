# DSH Token Manager · 配置指南

> 所有配置都在 Harness 的「Token 监控 → 设置」页修改，保存后立即生效（采集/分析类开关对后续事件生效）。
> 数据位置：`%DSH_HOME%\dsh-token-manager\token-manager.db`（SQLite，WAL），可用 `DSH_TOKEN_MANAGER_DATA_DIR` 覆盖目录。

## 1. 采集（全局）

| 配置 | 默认 | 说明 |
|---|---|---|
| 采集开关 | 开 | 关闭后不再写入新的调用/任务/缓存记录（历史数据保留） |
| 观察模式 | 开 | 只统计与分析，不修改模型上下文 |
| 仅提示不干预 | 开 | 异常只提醒，不阻断任务（本插件没有阻断能力） |
| 证据文本上限 | 200 | 发现项中保存的文本摘要最大字符数 |

## 2. 分析项开关与阈值

| 分析项 | 默认 | 阈值（默认） |
|---|---|---|
| 重复读取同一文件 | 开 | 重复读取次数 2（内容哈希相同才算） |
| 重复执行相同工具 | 开 | 重复工具次数 2 |
| 重复执行构建 / 测试 / 部署 | 开 | 重复命令次数 2（命令归一化后比较） |
| 多轮确认检测 | 开 | 确认消息字数上限 240；确认轮数 2 |
| 重复计划检测 / 重复总结检测 | 开 | 重复文本次数 3 |
| 步骤膨胀检测 | 开 | 步骤膨胀倍数 1.5；简单修改调用上限 6；普通开发调用上限 15 |
| 缓存命中下降检测 | 开 | 缓存命中下降倍数 0.5（对比同项目历史中位数） |
| 任务成本异常检测 | 开 | 成本异常倍数 1.5；基线最少样本 5 |

说明：阈值按“同类型历史任务”的 p80 中位数比较；样本不足时不会给出异常结论。

## 3. 价格表（费用估算）

| 字段 | 说明 |
|---|---|
| Provider / 模型 | 与调用记录中的 `provider` / `model` 匹配（如 `deepseek-account` + `deepseek-flash`） |
| 未命中输入价 | 每单位 Token 的普通输入单价 |
| 缓存命中价 | 每单位 Token 的缓存读取单价 |
| 缓存写入价 | 每单位 Token 的缓存写入单价（DeepSeek 通常为 0） |
| 输出价 | 每单位 Token 的输出单价 |
| 币种 | CNY / USD |
| 单位 tokens | 默认 1000000（每百万 Token）；按你的账单单位填写 |
| 生效时间 | 同模型多条价格时取生效时间最新的一条 |

**示例（仅示范格式，不是官方报价，请填你自己的账单单价）：**

```
Provider: deepseek-account   模型: deepseek-flash
未命中输入价: 0.5   缓存命中价: 0.05   缓存写入价: 0   输出价: 1.0
币种: CNY   单位 tokens: 1000000
```

未配置价格时：界面显示「价格未配置」，只显示 Token 数量，**不会虚构费用**。

## 4. 工具输出缓存（Phase 2）

| 配置 | 默认 | 说明 |
|---|---|---|
| 模式 | 观察模式 | 关闭 / 观察模式（记录但不替换）/ 启用自动压缩（替换为摘要） |
| 最小处理字节 | 2048 | 小于该大小完全不处理 |
| 选择性摘要下限 | 10240 | 达到后允许选择性摘要 |
| 智能压缩下限 | 51200 | 达到后允许智能压缩 |
| 缓存上限 (MB) | 512 | blob 目录总容量，超出按最近访问淘汰 |
| 保留天数 | 30 | 超期缓存清理 |
| 类型开关 | 全开 | 纯文本 / 构建日志 / 测试输出 / JSON / XML / 文件列表 / ZIP 其他文本 |

- 缓存存储状态：显示 blob 数、占用、缺失数；「一致性检查」返回缺文件/孤儿文件/哈希不符计数；「清空缓存」需二次确认。
- 被替换的工具结果里会带 `Blob ID`；需要完整内容时模型可调用 `token_manager_read`（按 blobId 分页，或按会话工作目录内文件路径读取）。
- **不会压缩**：用户消息、系统/开发者消息、mnemon 记忆、提问类工具、错误结果、图片。

## 5. 上下文分析（Phase 3，只检测）

| 配置 | 默认 | 说明 |
|---|---|---|
| 模式 | 仅检测（dry-run） | 当前版本只有关闭/仅检测，没有“应用改写” |
| 最少出现次数 | 2 | 同一内容出现几次才算重复 |
| 最少节点数 | 4 | 少于该节点数的会话不分析 |
| 最大候选数 | 50 | 单次分析返回的候选上限 |
| 风险倍数 | 1.5 | 缓存失效成本 > 可节省成本 × 倍数 → 判风险 |
| 缓存读取价格比例 | 0.1 | 未配置价格时用于 Token 代理估算的缓存读取比例 |

- 分析范围：仅当前进程中的 live 会话（需先打开会话）。
- `dsh-mnemon`、system/developer/user 等来源一律「受保护」，不产生候选。
- 「记录本次 dry-run 建议」只写入本地 `optimization_records`（status=proposed），不改任何会话。

## 6. 任务与项目（Phase 4）

- 任务：自动任务（每个用户 turn）+ 手动任务；可改名、改类型（简单修改/普通开发/复杂开发/故障排查/项目分析）、改状态（待开始/执行中/已完成/已暂停/失败）、合并。
- 任务摘要 9 段：本次目标 / 实际完成内容 / 关键技术决策 / 修改文件 / 接口变化 / 测试结果 / 未完成事项 / 下一步计划 / Token 使用统计。自动草稿只用本地数据生成，不调用模型。
- 项目摘要 8 段：项目基本情况 / 技术架构 / 数据库结构 / 关键接口 / 已完成模块 / 当前开发状态 / 未完成事项 / 用户明确限制。版本化保存（每次保存版本 +1），可导出 JSON / Markdown。
- 项目摘要只保存在本插件数据库，**不会自动写入 dsh-mnemon**。

## 7. AUTO 自动推理（Phase 5）

入口有两处：composer 模型选择器旁的 **AUTO 控件**（AUTO / OFF / LOW / HIGH / MAX + 最近决策），以及本插件「设置 → AUTO 自动推理」。AUTO 与手动档位互斥：在官方选择器里手动选任何档位 = 退出 AUTO（`settings.auto.enabled=false`），手动模式行为与旧版完全一致。

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用 AUTO 自动推理 | 关 | 关闭时插件**绝不**调用 `agent.model.select()`，不写决策 |
| 子 Agent 也纳入 AUTO | 开 | 子会话同样按任务难度选择档位 |
| 观察模式（只记录不生效） | 关 | 记录决策但 `applied=0`，不真正改档位 |
| 新任务重新判断 | 开 | 每个新用户 turn 重新分类，不继承上一任务档位 |
| 初始档位（简单修改） | 关闭推理 | 简单 UI/文案/查询/简单文件与命令 |
| 初始档位（普通开发/复杂开发/故障排查/项目分析） | 低推理 | 复杂任务也从 LOW 开始，靠证据逐级升级 |
| 初始档位上限 | 低推理 | 硬保证：任务第一步不会是 HIGH/MAX |
| 推理失败升级次数 | 2 | 同任务内「推理性失败」累计到此值升一档 |
| 复杂任务文件数 | 3 | 写文件达到该数量视为复杂，可升一档 |
| 最大无进展步数 | 40 | 兜底升级条件 |
| 单任务最大升级 | 3 | 最多 OFF→LOW→HIGH→MAX 三次 |

### 升级规则（逐级、只升不降、一次一档）

`OFF → LOW → HIGH → MAX`。触发升级的证据只有：写文件数达到阈值、推理性失败累计、已尝试多种方案仍失败、步骤数兜底。**环境类失败绝不升级**：文件/路径不存在、权限不足、依赖缺失、网络失败、命令不存在、测试环境问题、外部 API 不可用、端口占用、沙箱拒绝等，只记录到 `failureKinds`。

### 决策留痕

每次 AUTO 决策写入 `auto_decisions`（时间/会话/轮/步/任务类型/原档位/新档位/阶段/动作/原因/证据/是否生效），可在「成本分析 → 最近 AUTO 决策」查看。失败原因、当前任务类型与档位也会在 AUTO 菜单里显示。

## 8. 上下文优化（Phase 5）

| 配置 | 默认 | 说明 |
|---|---|---|
| 上下文复用（contextReuse.mode） | `observe` | `off` / `observe`（只记录不替换）/ `on`（替换为引用） |
| 最小复用字节 | 512 | 小于该值的工具结果不参与 |
| 单会话登记上限 | 512 条 | 防无限增长 |
| 上下文包预算 | 6000 字符 | `token_manager_context` 工具的默认硬预算 |
| 子 Agent 审计 | 开 | 记录 spawn/fork、委派 prompt 字节、子会话 token |

- **上下文复用**：同一会话内第二次及以后读到的**完全相同**工具结果（tool+args+result 哈希一致、≥512B）会被替换为一条极小的引用（含可恢复的 `Blob ID`），模型需要原文时调用 `token_manager_read`。默认只观察、不替换；`on` 模式实测模型能正确理解引用并继续任务。
- **子 Agent 审计**：`subagent_runs` 记录 provider（spawn=fresh 不继承父历史 / fork=继承父历史快照）、委派 prompt 字节、子会话 input/output/cache token、调用数；对「fork 继承完整历史」与「委派 prompt 过大」产生发现项。
- **`token_manager_context` 工具**：按需返回分层最小上下文包（项目 8 段 + 当前任务 9 段与最近决策 + 最近变更文件），受字符预算约束并显式标注省略；用于委派子 Agent 或长会话续接时替代粘贴完整历史。返回的是摘要，不是原文。
- **不改变 Harness 核心**：AUTO 通过 `agent.model.select()`（步骤准备前）实现，未修改 Harness 源码、未改写历史消息、未绕过压缩/缓存机制。

## 9. 数据导出与备份

- 调用明细：CSV（UTF-8 BOM，防公式注入）。
- 任务报告：JSON / Markdown / CSV。
- 项目摘要：JSON / Markdown。
- 整库备份：先关闭 Harness，复制 `%DSH_HOME%\dsh-token-manager\` 整个目录；恢复时覆盖回去（同时删除 `-wal` / `-shm` 残留）。

## 10. 恢复默认

设置页右上角「恢复默认」会把采集/分析/阈值/缓存/上下文/AUTO 配置恢复为默认值（价格表、任务与项目摘要、统计数据不受影响）。
