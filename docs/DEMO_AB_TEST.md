> 环境：DSH 0.2.1-rc.5，模型 `deepseek-account / deepseek-flash / reasoningEffort=high`；生产 profile `desktop`（含 dsh-mnemon）。

## 1. 安装结果（生产 profile）

- 通过插件管理器安装：`dsh-token-manager 1.0.0`，`application: applied`，无 warning。
- 页面刷新后左栏出现「Token 监控」（与「记忆系统」共存）；`/token-manager/api/health` 返回 `ok:true`、schema v4。
- 模型侧可调用工具清单新增 `token_manager_read`（证明 Host 半已激活）。
- 压缩模式保持 **观察模式（observe）**：只记录不替换，生产行为不受影响。

## 4. 受控对照实验（同一 profile：tm-control，仅切换插件/压缩）

任务：让模型执行 pwsh 生成约 64KB 输出，再作答。

| 组 | 插件 | 压缩模式 | 调用次数 | 未命中输入 | 缓存读取 | 输出 | **合计 Token** |
|---|---|---|---|---|---|---|---|
| A | 无插件 | — | 2 | 20,988 | 22,784 | 295 | **44,067** |
| B | 有插件 | 观察（不替换） | 2 | 21,031 | 23,296 | 526 | **44,853** |
| C | 有插件 | 启用自动压缩 | 2 | 1,566 | 28,416 | 86 | **30,068** |

- A→B：`+786`（约 +1.8%），主要来自工具清单多一个 `token_manager_read` schema + 模型输出波动（526 vs 295）。
- A→C：`−13,999`（约 **−31.8%**），因为 64KB 工具输出被替换为 4.2KB 摘要（`tool_results`：original 64,143 → compressed 4,348，`smart`）。
- C 的官方投影与插件台账一致（1,566 / 28,416 / 0 / 86）。

## 5. 结论与边界

- 插件在“观察模式”下**几乎不改变 Token 消耗**（差异为工具 schema 与模型波动）；它提供的是**可见、可核对**的计量。
- 开启“自动压缩”后，大工具输出场景出现明显 Token 下降（本次单次实验 −31.8%），原因是模型不再重复接收 64KB 原文。
- 本次是**单次演示**，不是统计意义上的 A/B；模型输出、缓存前缀状态每次不同。要宣称“普遍节省”，需按 PRD 12.4 做多次同任务对照。
- 生产当前保持“观察模式”；如需启用自动压缩，建议先在测试 profile 观察几天再切换。
